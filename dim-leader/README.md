# dim-leader - 圆心引线标注

对"共圆心的两个半圆弧"的圆心，用多段线引线标注其旁的单行文本；文本自动分层、
可多列横向错开、并可按需旋转 90°，使标注文字互不重叠，同时尽量缩短引线。

典型场景：测量图里成片的高程点标注（`161-1261.63` 这类"点号-高程"）挤在一起，
需要把文字挪开、加上引线指回原圆心。

## 工作原理

```
① 找圆心   全图 ARC → 按圆心分组 → 恰好 2 条且各跨 180° 的圆弧 → 取其圆心
② 配文本   TEXT 的对齐点(组码 11，缺失取 10) 落在 圆心±offset 处 → 一对一贪心匹配
③ 排布局   按所选布局算法为每个标签选锚点与引线折点
④ 落图     改写 TEXT 的 10/11/50(/72/73) + 逐条 entmake LWPOLYLINE 引线
```

第 ④ 步会把匹配到的文本**移动**到新位置，原始位置不再保留；未参与标注的 TEXT
会作为障碍物参与避让。

## 9 种布局怎么选

下表的"文字重叠"是 **507 点真实图纸实测**，"引线交叉"由 `verify_layouts.py` 从落盘文件独立算出：

| 布局 | 引线特征 | 实测文字重叠 | 引线交叉 | 适用 |
|------|----------|------------:|--------:|------|
| 0 本地错开 | 3 段正交，可带绕行走廊 | 39 | 2395 | 零散点、要保持"就近" |
| 1 右侧表格 | 4 段正交，独占水平轨道 | 0 | 35899 | 整齐成表的成果表 |
| 2 分区表格 | 4 段正交 | 0 | 4257 | 纵向分布广的带状点群 |
| 3 二维分区 | 4 段正交，走无字横通道 | **370** | 21955 | 点群密集且形状不规则 |
| 4 四向 | 2 点直线 | 0 | 2675 | 希望文字向四向散开 |
| 5 分向轨道 | 4 段正交，独占轨道 | 0 | 25408 | 大范围点群 |
| 6 芯片式 | 正交通道搜索 + keepout | — | — | **实测不可用，见已知限制** |
| 7 紧凑双侧 | 3 段正交，每条独占 lane | 0 | 2959 | 兼顾紧凑与可读，配色区分引线 |
| 8 通道布线 | 4~5 段正交，四带 + 泳道 | 0 | **779** | **默认推荐**，密集点群 |

**"文字重叠 0" 不等于"引线不交叉"** —— 除了布局 8，其余布局都有数千到三万处交叉。
布局 8 是唯一压到千级以内的（779），其次是布局 0（2395）。

> 交叉数的定义：**一横一竖的相交**才算（T 形相接算，共线重叠与平行不算）。
> 早期版本只判"同向共线"、其余默认算交叉，会把两条不同高的水平引线误计，
> 数据虚高 2~5 倍 —— 详见 PLAN.md N17。`verify_layouts.py` 的 `_selftest()` 锁住了这个语义。

### 布局 8 的实测质量指标

"零共线重叠"指引线之间没有**共线重叠**（两条引线走在同一条线上）。
**交叉**（X 形相交）是另一回事。**2026-09-29 在 192.168.1.53（AutoCAD 24.1s）实测**，
507 点 `高程点图_局部.dwg`，布局耗时取 `MILLISECS`，质量指标由本机 Python 复算：

| 配置 | 布局耗时 | 平均引线 | 折点 | 引线交叉 | 引线穿文字盒 | 文字盒重叠 |
|---|---:|---:|---:|---:|---:|---:|
| `blocks=10` 旧默认 | 610 ms | 224.8 | 1328 | 13700 | 497 | 0 |
| **`blocks=0` 新默认（夹到本行范围）** | **234 ms** | 221.6 | 990 | **779（−94%）** | **19（−96%）** | **0** |

端到端复核：`(dim-leader:run-layout 8)` 全流程 1859 ms，建出 507 条 LWPOLYLINE、移动 507 个 TEXT；
把图上**实际画出的** 507 条折线与布局计算结果逐点比对，**配对失败 0、逐点误差 0**，
两条路径算出的交叉数同为 779。落图后抽查 TEXT 的 10/11/50/40/72/73，图层仍为原图层 `点图2`，引线颜色循环（组码 62）生效。

规模曲线（`blocks=0` 新默认，本机 Python）：

| 点数 | 耗时 | 平均引线 | 交叉 | 穿文字盒 | 盒重叠 |
|---:|---:|---:|---:|---:|---:|
| 100 | 1.9 ms | 42.6 | 114 | 0 | 0 |
| 200 | 4.0 ms | 108.5 | 606 | 1 | 0 |
| 507 | 11.8 ms | 221.6 | 779 | 19 | 0 |

## 配置项

通过 `(@:get-config 'dim-leader:xxx)` / `(@:set-config 'dim-leader:xxx 值)` 访问，
或用菜单里的"参数设置…"。

| 配置键 | 默认值 | 说明 |
|--------|--------|------|
| `dim-leader:layout` | `0` | 布局编号，见上表 |
| `dim-leader:layer` | `""` | 引线所在图层；为空时用文字图元原图层（见已知限制） |
| `dim-leader:offset` | `2.0` | 文本相对圆心的水平匹配距离 |
| `dim-leader:match-tol` | `0.5` | 文本匹配容差 |
| `dim-leader:gap` | `1.0` | 文字分层/分列的间隙 |
| `dim-leader:columns` | `4` | 布局 0 允许横向错开的最大列数 |
| `dim-leader:avoid-leader` | `0` | 布局 0 是否让文字避开引线（1 开，明显变慢） |
| `dim-leader:zones` | `8` | 布局 2 的分带数 |
| `dim-leader:rotate` | `1` | 是否允许把部分文本旋转 90° |
| `dim-leader:leader-width` | `nil` | 引线宽度，nil 为细线 |
| `dim-leader:side-distance` | `10.0` | 布局 7：文字带距点群边界的距离 |
| `dim-leader:leader-colors` | `"1 3 5 2 4 6 30 40"` | 引线循环颜色（ACI，空格分隔；空串不配色） |
| `dim-leader:lane-gap` | `1.0` | 布局 8：相邻平行引线的通道间距 |
| `dim-leader:channels-lines` | `0` | 布局 8：每带行/列数，0=按范围自动 |
| `dim-leader:channels-columns` | `1` | 布局 8：列位算法，1=最小位移保序（引线更短），0=等距 |
| `dim-leader:channels-blocks` | `0` | 布局 8：文本带分块数，>=2 时块间留贯穿缝隙（**不推荐**，见下） |

> 布局 8 早期默认 `channels-blocks=10`，靠块间缝隙让深行引线穿缝，以减少"引线穿文字盒"。
> 现已改为不分块：把每行标签夹到**该行自己**的点范围内之后，不分块路径在这两项上都大幅更优
> （507 点实测 穿文字盒 497→19、引线交叉 13700→779），分块路径反而被完全支配。

## 使用示例

```lisp
;; 用布局 8 跑（菜单里点"8 通道布线"等价于此）
(dim-leader:run-layout 8)

;; 让文本压引线的情况少一些：关掉 90° 旋转、加大列数
(@:set-config 'dim-leader:rotate 0)
(@:set-config 'dim-leader:columns 6)
(dim-leader:run)

;; 布局 8 换更紧凑的排布：分块 + 等距列位
(@:set-config 'dim-leader:channels-blocks 4)
(@:set-config 'dim-leader:channels-columns 0)
(dim-leader:run)
```

## 已知限制

| 问题 | 表现 | 说明 |
|------|------|------|
| 布局 6 大图不可用 | 507 点需数小时，且常返回"无可用正交通道" | 代价是 `标签数 × 通道候选 × (障碍盒+keepout)`，约 n^1.7 |
| 布局 0 / 4 为 O(n³) | 507 点布局 4 约 3.8 s；布局 0 单次即超 30 s | `box-hit-p` 遍历全部已放置项，缺空间索引（PLAN.md I6/R4） |
| 布局 0 找不到空位仍落位 | 507 点实测 203 处文字盒重叠 | `(> o 400)` 强行置位后仍生成 `best`（PLAN.md I2） |
| 布局 8 仍有引线交叉 | 507 点实测 779 处 | 竖臂 256 点挤在 46×176 的窄带里，行距 4 时一行只放得下 44 个 → 必须堆 6 行，深层行的引线要越过外层泳道。带越窄这个代价越大（见上表） |
| 布局 3 有文字重叠 | 507 点实测 370 处 | 二维分区的空白矩形搜索疑似没把已放置标签回填（PLAN.md N15） |
| **布局 6 芯片式实际不可用** | **只喂 5 个点也跑不完**，CAD 阻塞约 10 分钟需人工恢复 | 代价是 `标签数 × 通道候选 × (障碍盒+keepout)`，约 n^1.7 且常数极大。菜单里点错一次就要等 CAD 假死，建议先从菜单摘掉（PLAN.md N16） |
| `layer` 为空时落 CLAYER | 引线没跟着文字原图层走 | 实现里省略了组码 8（PLAN.md I3） |
| 只支持 0°/90° 旋转 | 竖排居中文字的避让盒偏半个字长 | `text-box` 忽略 72/73；已在 CAD 上实测复现（PLAN.md I4） |
| MTEXT 被静默丢弃 | 选了 MTEXT 却不做标注 | 匹配阶段只收 TEXT（PLAN.md I9） |
| 角度组码按弧度 | 换 CAD 可能要改 | 本 CAD 的组码 50/51 以弧度计，`place-text` 按此写入 |

`PLAN.md` 里还有回滚、undo 组、试运行、配置对话框等条目，尚未实现。

- ※ 布局 0 的历史值是网格索引修复前测的；等价的 507 点合成场景（文字较窄）下曾实测 25 266 ms。
- 15–31 ms 的双值是真实抖动：这几个布局已接近 `MILLISECS` 计时与 62 ms `entget`+`textbox` 度量基线的量级，重测会跳档。
- Python 侧刻意与 LISP 逐句对照（含 `vl-sort` 保序、`fix` 截断、`cons/reverse` 顺序），**不做任何优化**。
  **但对照必须双向核对** —— 2026-09 两次发现两边不一致，且方向相反：
  - Python 的 `ch_isotonic`（PAVA）有 bug（先建好全部块再回头扫，合并只发生在末尾两块），**LISP 是对的**（PLAN.md N11）；
  - LISP 的 `grid-add` 漏插桶，**Python 是对的**（PLAN.md N14）。
  只照抄镜像结构、或只测单个布局，两次都会漏掉其中一半。
- 布局 6 的代价是 `标签数 × 通道候选 × (障碍盒+keepout)`。实测 5 个点就跑不完并阻塞 CAD 十余分钟，比旧记载的"4 个点 2.2 s"严重得多，**不要在生产图上试**。
