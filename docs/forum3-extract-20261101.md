## 2. 本次采纳

### 2.1 幻灯片库名称读取（thread-113336）

原帖给出完整 `gxl-slb2sldnames`。原实现的问题：

- 依赖「首条偏移 + 37」判断结束，头长度/偏移差 1 就会多读一条；
- `read-char` 在 EOF 返回 `-1`，在 AutoLISP 里是真值，可能把 `-1` 塞进字符串；
- 名称没有去除空格填充。

按 SLB 目录结构重写（`packages/at-library/slb.lsp`）：

```lisp
;; 31 字节文件头 + N × (32 字节名称 + 4 字节偏移)
;; N = (文件大小 - 31) / 36
(setq count (fix (/ (- size 31) 36)))
```

提供：

| 函数 | 说明 |
|---|---|
| `at-library:slb-names file` | 返回名称列表，失败 nil |
| `at-library:ai-slb-names file` | AI 入口，无交互 |
| `at-library:slb-list` | 交互选 `.slb` 并打印名称 |

CAD 实测：合成 3 条目的 SLB → `(SLIDE1 SLIDE2 SLIDE3)`。

### 2.2 图纸自动备份（thread-101521）

原帖是反应器方案（按自动保存间隔备份 + 保留份数）。本项目采纳**手动/AI 触发**的简化版，
不做保存反应器（避免每次保存阻塞、与批量脚本冲突）：

- `at-session:ai-backup-current (dest keep)`：复制当前已保存 DWG 到
  `图纸目录/备份/原文件名-YYYYMMDD-HHMMSS.dwg`，只保留最新 `keep` 份；
- `at-session:backup-current`：交互入口；
- 当前图纸未保存、目录不可写、文件被占用时返回 nil 并 `princ` 原因。

CAD 实测：保存 `live.dwg` → 连续备份两次（keep=1）→ 只剩最新一份，文件名带时间戳。

## 4. 不采纳与理由

- **文字合并（171203）**：`at-text:ai-join-text` 已实现按位置排序 + 换行连接，功能等价；
- **线型长度统计（193095）**：`at-stat/count.lsp` 已有按图层分层统计 + 表格；
- **连续标注（195036）**：`at-dim` 已有连续取点标注，只是没有「前两点自动判线性/对齐」的包装，
  价值不足以单独开项；
- **EAN-13（89727）**：`qrencode` 目前只做二维码；条码是垂直场景，代码需登录，暂不投入；
- **错误处理（100616）**：文章质量高，但属于编码规范；已通过 `atlisp-lint` 的
  `command without *error*` 提示逐包治理，不新增运行时库。

## 5. 结论

1. forum-3 的高价值集中在 **2010–2015 年的 Gu_xl 经典源码**（局部放大、Block→Lisp、
   Excel→CAD、拓扑算法），浏览/回复远高于近期的工具帖。
2. 其中「代码完整可见」且能快速落地的是 **SLB 名称读取** 与 **图纸备份**，本次已采纳并实测。
3. 局部放大、Block→Lisp、Excel→CAD 体量在 M/L，且原实现带大量私有辅助函数/附件，
   不应直接拷贝；已转成待审批计划，按项目规范重写。
4. 近期热帖（图库、FAS 编译器、PAT 预览）大多已被现有包覆盖，重复建设风险高。
